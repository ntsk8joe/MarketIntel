# 开源发布指南

代码已按 MIT 准备。建议发布代码，让每位使用者在自己的电脑配置供应商账号与研究库，不将个人数据作为默认演示分发。

## 已完成的修改

| 发布问题 | 处理 |
|---|---|
| 用户 API Key | 工作台填写并保存在本机 config/connections.json；不回显、不导出、不备份；支持清除与环境变量兼容 |
| 凭据误提交 | .gitignore 排除 config、.env 与环境副本，只保留空 .env.example |
| 私人知识库 | 整个 vault、根目录 Obsidian 配置、数据库、原始响应、备份均排除 |
| 机器绝对路径 | 启动脚本与浏览器测试改为本机 Python / 标准依赖，不依赖作者的开发工具目录 |
| 第一次启动 | 默认空库，历史示例使用 --demo 显式导入；默认无采集许可、无自动追踪 |
| 意外读取报告 | 移除从父目录自动查找并复制个人研究报告的逻辑；已保存数据不删除 |
| 许可证 | 添加 MIT LICENSE；代码许可证不替代第三方资料或依赖的许可 |
| 基础协作 | README、SECURITY、CONTRIBUTING 和 GitHub Actions 测试工作流 |
| 发布打包 | prepare_release.py 只包含明确列出的代码与文档，不递归打包整个项目 |

## 生成和检查发布包

```sh
python3 -m unittest discover -s tests -v
python3 tools/prepare_release.py
```

产生 `release/marketintel-source.zip`，不含现有数据库、知识库、采集原文、配置、备份和个人报告。打包器检测部分已知密钥形式与个人绝对路径；**它不是完整的秘密扫描器**，发布前还应人工审核文件，并使用 gitleaks 等专用工具检查暂存内容及历史。

本次本地验收：Python 3.9 和 3.12 各通过 64 项测试；浏览器完成 15 项操作检查及 5 种宽度下的 8 个页面检查，详见 [安全回归报告](安全回归报告.md)。GitHub Actions 需要在上传后查看真实运行结果；Windows 启动脚本尚未在 Windows 机器验收。真实付费接口仍需用户配置自己的账号验证。

最稳妥的第一次发布方法：解压这个源码包到一个新目录，检查其内容，在该目录建立新仓库，再上传代码。不要直接打包整个当前工作目录。发布之前核对 LICENSE 中的署名；目前使用项目署名 MarketIntel contributors，可改成你希望公开使用的署名。

在新目录中操作，下面的命令只准备本地仓库：

```sh
git init -b main
git add app.py marketintel web tests tools docs .github README.md LICENSE SECURITY.md CONTRIBUTING.md .gitignore .env.example start.command start.bat
git diff --cached --name-only
git diff --cached
```

确认没有凭据、个人资料或无权分发的文件后，再提交；GitHub 仓库地址需要使用自己创建的仓库地址。生成发布包和上述本地准备命令不会自动创建远端仓库或上传文件。

## Key 的正确使用方式

每位用户打开本地工作台填写自己的 Key，费用由其自己的账号承担。连接配置文件是明文，在 POSIX 中只允许拥有者访问；Windows 用户需检查该目录的权限。程序不把 Key 写入前端静态代码或 localStorage，不保存到研究数据库。

Key 已配置只表示“有值”，不表示账号有效、有额度或具备模型权限。保存配置不会调用供应商；运行 Actor、关键词查询或 AI 研判时才调用相应账号。已启动的付费任务不会因为清除 Key 而自动停止。

当前使用方式是每个人下载代码独立本地运行。如果未来做共享的在线 SaaS，需要另做登录、每用户凭据隔离、加密保存、访问控制、费用配额和审计；当前本机服务不能直接作为共享线上站点使用。

## 第三方资料与许可证

源码发布包没有实际采集的网页原文或个人社区讨论集合。公开访问不自动意味着允许重新分发；引用、数据源 API、Actor 及下载的数据各自遵守对应规则。代码的 MIT 许可不自动给第三方内容授予许可。

核心运行依赖 Python 标准库，不打包 Python、Chrome、Obsidian、字体或第三方图像。Playwright 只是可选开发测试依赖，通过其官方渠道安装。新增依赖或素材时，应记录来源与原许可证。

- [GitHub：仓库许可证](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)
- [MIT 说明与标准文本](https://choosealicense.com/licenses/mit/)
- [GitHub：移除敏感数据](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)
- [Playwright 官方安装与库用法](https://playwright.dev/docs/library)

如果秘密曾经提交，先撤销/轮换，再处理 Git 历史与其他副本；仅从当前文件删掉秘密或加入 .gitignore 不够。不要向公开 issue 上传研究库、付款信息、密钥截图或供应商完整错误响应。
